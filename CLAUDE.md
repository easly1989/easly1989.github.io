# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Carlo Ruggiero's personal project site, served by GitHub Pages from the root of
`main` at https://easly1989.github.io. There is no package manager and no CI: the
`.html`, `.css`, `.js` and `.svg` files in the repo are exactly what ships, and a push
to `main` is a deploy. The one build step is local and committed: `python tools/sync.py`
writes each project's facts from `data/projects/` into the pages (see The things that
are coupled).

The site has two faces:

- **The professional home**, the default for everyone on every device: a plain page
  with the name, one line, the reach links, a ruled row per project, About and a footer,
  and a professional page per project, `pro/<id>.html`.
- **The room**, which a reader chooses from it: the bench, a cutting mat with one
  object per project, lying on a desk in an isometric room lit by a WebGL light pass,
  with Willy, a 3D cat, living there. Its objects open the playful project pages, which
  keep the bench's style (the mat, paper, tape).

## The professional home

`index.html` holds both homes. The professional one (`<div class="pro">`, styled by `pro.css`
alone) reads in full with scripts off. Its rows are generated by `tools/sync.py`
(`<id>.pro-row`) and each leads to `pro/<id>.html`, also generated, whole, from the data
(`pro/README.md`). The professional pages never link to the playful ones, and load nothing of
the room: no `styles.css`, no Willy, no three.js. Its first focusable thing is "Skip to the
projects", shown only while it has the focus.

The way into the room is Willy peeking over the top rule of the project list, an inline SVG,
with "Step into the room" (`href="?room"`). He shows only where the room would fit
(`html.room-fits`), so never on a phone and never without scripts. There, the home's inline
script has his eyes and head follow a mouse, and a paw swat at it when it comes close or onto
the link, or when the link takes the keyboard focus; under reduced motion, for touch and for a
pen he stays still (`pro/README.md`, `checks/peek.py`).

## The room, and choosing it

The first script in `index.html`'s head decides. The room shows only when `localStorage`
`site:room` is `"1"` and the window holds it: wider than 900px, with a mouse or a trackpad
(`any-pointer: fine`, so a phone in landscape never qualifies), at a scale of 0.7 or more
(`ROOM_FIT`; `room.js` keeps the box it needs in `localStorage` `room-box`, and before it has
measured one the head assumes the room's usual box). Willy's peek shows on the same terms. Then it adds
`html.iso`, takes `pro.css` away and writes `styles.css`, the room's fonts, `room.css` and the
room's modules into the head; a script after the mat un-hides it and hides the professional
page; the end of the body writes `crt.js`, `radio.js`, `photos.js`, `room.js` and `morph.js`.
So a professional visitor downloads none of them. Otherwise it is the professional page,
whatever was chosen: a phone never gets the room.

- `?room` and `?room=0` set the key (and the visit's `sessionStorage` `room`, which About and the
  radio read), and the head then takes `room` out of the address with `replaceState`, so a
  reload or a copied link never chooses again.
- **The tie** hangs over the back of the room's office chair: a link with its tag, "Plain
  version". Picked up, it is put on (it lifts and swings once, `room.css`) and the plain home
  opens: `room.js` sets `site:room` to `"0"`, removes `sessionStorage` `room` and goes to
  `index.html`, with no query. Under reduced motion, and on Shift, Ctrl or Cmd-click, there is
  no move. The room's first focusable thing, "Plain version of this site", shown only while it
  has the focus, does the same. Coming back to the room by Back (the back/forward cache), the room
  is chosen again.

The room is built by `room.js` from the bench's markup in `<div class="mat" hidden>`, before the
first frame (`#room-ready` holds it), and framed to the window: it scales until every link and
button in it fits with a margin. A new link in the room must sit inside that box, or the room
is drawn smaller at every size: check `checks/framing.py` and the scale at 1280×720, 1440×900
and 1920×1080. `room-light.js` is the light pass (it follows what moves, `MOVERS`),
`room-mouse.js` the computer's mouse, `room-plush.js` the crab on the wall, `radio.js` the radio
on the shelf (it carries on from page to page in a visit to the room), `photos.js` the camera's
photos.

## Working on it

Serve the repo root with `python checks/serve.py`: it sends `Cache-Control: no-cache`, so a
reload after an edit gets the new file (plain `python -m http.server` lets the browser cache
the scripts hard). Not `no-store`: it also keeps every page out of the back/forward cache, so
going back reloads the page, and readers' back is never tested. Reload rather than going back,
which may bring the page back as it was; or check what the page actually loaded.

Verification: load the affected page, check both colour schemes (`prefers-color-scheme` light
and dark are both styled), phone width, and `prefers-reduced-motion: reduce`, under which
nothing may move on its own: books arrive open, the About photo arrives developed, there are no
page transitions or opening moves, Willy sleeps, and his peek on the professional home is still.
Then the checks in `checks/README.md`.

**This PC's Chrome reports reduced motion by default** (Windows' animation effects are off):
a check or a test of motion must emulate `prefers-reduced-motion: no-preference`, or Willy never
walks and nothing moves.

Motion needs a browser that is actually painting. Willy, the books and every transition run per
frame, so in a hidden, throttled or offscreen preview none of it appears to work while the
static layout is fine. Headless Chrome is unreliable for the page transitions in particular: it
skips some of them at random.

When checking layout by script, load lazy images first (`img.loading = "eager"` and wait), or
every book page and screenshot measures as if it had no picture. Measure rotated elements with
`offsetWidth`/`offsetHeight`; `getBoundingClientRect()` returns the rotated box.

**Never write a file by opening it for writing before reading it.** In Python,
`open(p, "wb").write(open(p, "rb").read())` truncates the file before the read runs, and the
file is gone. Read into a variable first, then open for writing. This wiped six files in one
command during an earlier redesign; nothing was committed, so they had to be rebuilt by hand.

## The bench's objects, in the room

Each project is one object on the bench, and picking it up plays a move before its page opens
(`morph.js`): it rises straight up, turns to face the reader and morphs into its page's
counterpart. The mug tips over and its coffee floods the view (the way to Donate), the instant
camera fires its flash and ejects a print (the way to About), the sticky note peels off into
the Write to me sheet, and the felt crab (Claude stuff), hung on the back wall by its suction
cup, is tugged by its cord and bounces. Pointing at an object, or focusing it, brings out a
paper tag with its name. Shift, Ctrl or Cmd-click and reduced motion skip the move and just
navigate. Coming back through the back/forward cache puts every object down again.

A room object is `<a class="thing">` with `data-open="<move>"` and `data-open-ms`. The crab
(`.thing.plush`) is drawn live by `room-plush.js` in a canvas flat on the wall, lit again by the
room's light pass; without WebGL 2 its picture shows instead. Its canvas must stay short of the
room's corner, and its link is the box round the toy but for the top of its far edge, which
would make the room's frame smaller (`.plush-hit` makes up the 44 px). It is named "Claude
stuff" and leads to `coordinator-monitor.html` for now. Pointing it at a hub page later means its
`href` in `index.html`, the words that describe where it leads (its `aria-label` and small line,
`home` in `data/projects/coordinator-monitor.json`, and the contact sheet's option), and the new
page's morph entries (`morph.js` PAIRS and POSE, the page's `view-transition-name: crab`,
`checks/moves.py`).

Every playful page opens with a label sheet (`.paper.label-sheet`): the status line (`.state`),
the name, one lede and the actions. Below it, each page is its object opened up: CloudBank the
ledger, Nutreek the agenda (open on this week, today's page marked), Social Contacts Sync a grid
of contact cards, Planora the vote card, the lifecycle on a string and the idea jar, Cupid the
letter out of its envelope, About the photo developing, Donate the spilled coffee and the sugar
packets. Screenshots are taped prints, `<figure class="shot">` with a `<figcaption>`; `site.js`
wraps each `.shot img` in a `<button class="zoom">` that opens the shared lightbox. Every
screenshot carries its real `width` and `height` and `loading="lazy"`.

The loose desk items (pencil, eraser, clip, coin) are scenery, with no behaviour.

## Books

`.book` is a book you can leaf through: `.leaf` elements, each with a
`.page.front` and a `.page.back`, turned in 3D. `site.js` builds a corner to
turn on every page, wires the side tabs (`.tabs [data-go="<spread>"]`), the
previous and next buttons and the arrow keys, and makes every page that is not
showing `inert`. A book arrives closed and opens; `data-open-to` makes it go on
to a spread, which is how the Nutreek agenda opens on today. Under 900px a book
is simply its pages in a column, all of them readable.

A page has a fixed height. Adding content to one means checking it still fits,
with its images loaded, at 1280, 1100 and 960 wide.

## Between pages

The browser morphs one page into the next (`@view-transition { navigation: auto; }` in
`styles.css`): the mat and the header stay, the object picked up becomes its page's counterpart,
and the rest cross-fades. Where cross-document view transitions are not supported (Firefox,
today) the pages simply load, and nothing else depends on them. Under reduced motion there are
none. The professional pages have no morphs.

The pairs are made by `view-transition-name`, one per page and unique on it; in the room
`morph.js` names the object only for the trip (its PAIRS):

| Room | Page | Name |
|---|---|---|
| `#ledger` | `cloudbank.html` `#ledger` (the book) | `cloudbank` |
| `#agenda` | `nutreek.html` `#agenda` (the book) | `nutreek` |
| `.thing.cards` | `social-contacts-sync.html` `.label-sheet` | `scs` |
| `.jar .jar-idea` | `planora.html` `.label-sheet` | `planora` |
| `.thing.envelope` | `cupid.html` `.env` | `cupid` |
| `.thing.pager` | `asf-plugins.html` `.label-sheet` | `asf` |
| `.thing.plush` | `coordinator-monitor.html` `.label-sheet` | `crab` |
| `.mug .cup`, the coffee | `donate.html` `.spill .cup`, `.spill .puddle` | `mug`, `puddle` |
| `.camera .film` | `about.html` `.instant` | `photo` |
| `.pc .glass` | `terminal.html` `.crt` | `crt` |

`header.bar` is named `bar` on every playful page. A duplicate name cancels the transition
silently, so a new name needs a check on both pages (`checks/moves.py`).

## A family page

`asf-plugins.html` is the page for several pieces of one platform: a label sheet for the family,
then one kraft folder (`.fam-folder[data-tabs]`) with a tab per piece. Another family page
copies its structure, and its facts go in a data file with one entry per piece under `members`,
with the markers of `asf-plugins.html` (each sheet's `state`, `name`, `lede` and `actions`,
each tab's `tab`).

- `.fam-tabs` holds one `a.fam-tab` per piece, `href="#<sheet id>"`, `style="--c: <accent>"`,
  with `<b>` the name and `<small>` the status. Each sheet is `section.fam-sheet#<id>` with
  `aria-labelledby` on its `h2`, `header.fam-head` (mark, `.state`, name, `.lede`, `.actions`),
  then its own blocks (a feed, a taped screenshot) and `.fam-grid` of `article.fam-card` (`h3`).
  The sheet's own `--c` colours its buttons. `.fam-card.fam-shared` is the card above the folder.
- `site.js` makes `[data-tabs]` a real tablist: roving tabindex, arrows, Home and End, `hidden`
  on inactive sheets, `replaceState` when a tab is chosen. A hash that names an element inside a
  sheet (`#events`) opens that sheet and scrolls to it, smoothly unless reduced motion. Without
  the script every sheet shows, stacked, and the tabs are links.
- The new product accent goes into `:root` (6:1 against white). A new family page also needs its
  pager-like object in the room, its `morph.js` entry and its `checks/moves.py` row.

## Willy

Willy is the site's cat: a white cat with black patches, like the one in the photos on About, a
3D model with fur in the room (`willy*.js`). He lives on the desk, the cushion on the perch under
the window and the shelf, and does one of his everyday actions after another, picked at random
and weighted (`willy-life.js`), now and then saying so in a bubble; he knocks the computer's
mouse about. He keeps the room's light off until he is ready, at most as long as the dark lasts.
Without WebGL 2, or if anything fails, there is no Willy and the room is as it was. Under
reduced motion he sleeps.

On the professional home he is the drawing peeking in (The professional home). He is on no
other page: the playful pages have no cat.

## The computer

An easter egg, not a project: an old all-in-one computer drawn in CSS 3D on the
room's desk. Its markup, style and script are inline in `index.html` (`.pc`), and
run only in the room. Only its power button does anything until it
has booted; then the screen or the keyboard opens `terminal.html`, a green CRT
console with a fake filesystem, floppy disks, tab completion and a few hidden
commands.

**The hidden commands are sealed, and that is the point.** Each one is the key
(PBKDF2, then AES-GCM) to its own entry in the `VAULT` in `terminal.html`, so the
page holds no command and no hash of one. The commands, the programs they open
and the kit that seals them live outside the repo, in
`~/.claude-env/bench-terminal/` (its `kit/build_term.py` rewrites
`terminal.html`). Edit the console there, never in the built page, and never
write a command, or the name of what it opens, into this repo — not in a
comment, a commit message or a PR. The hints in the console are riddles on
purpose.

State, all in this browser: `sessionStorage pc:on` says the computer was
switched on; opening `terminal.html` without it shows a red FATAL screen and
sets `localStorage pc:fried`, after which the room's computer stays broken
(cracked, scorched) until site data is cleared. `localStorage pc:mute` is the
speaker button. Ten wrong commands, or three wrong passwords, play
`assets/tty0.mp4` in a loop until its window is closed.

`crt.js` makes every sound with Web Audio, nothing downloaded; it loads, not
deferred, before `site.js`, in the room only. `terminal.html` stands alone: it
loads `crt.js` and its own script, and not `styles.css`, `site.js` or the room.

## Motion

**The resting state is the visible one.** Everything that animates on its own ends where the
content is plainly visible, and a page whose scripts never load shows all of it: books are
readable pages, the About photo is a photo (its development is a CSS animation that ends at no
filter), the professional home is whole and Willy is simply absent or still. Never write a rule
that leaves content hidden unless something else runs.

Non-user-triggered motion is Willy, the opening moves and the page transitions. Decoration does
not loop forever: the mug's steam puffs three times and stops. The one exception, asked for: the
pager's screen in the room changes its message every 8 to 25 s and runs a long one to its end
and back; under reduced motion it shows one message, still, and in a hidden tab it waits. The
crab on the room's wall swings a few times as the room arrives (about 2.5 s) and when it is
pointed at, and comes to rest; once any object's move starts, or the computer is switched on, it
settles in a few frames and stays still until the move is over. Under reduced motion it never
moves. Willy's peek on the professional home moves only in answer to a mouse or the keyboard.

## Money and attribution

`donate.html` is the site's own page, and donation links point at it rather than
at any product's own donate page — sending people from this site to a product's
donate page reads as though the site were asking on that product's behalf.

**The page names no projects at all, on purpose.** It is about supporting the
work in general: the time to finish and maintain things, releasing more of them
openly, and hosting for the apps and demos. An earlier draft argued the case
project by project — CloudBank is free, Planora is hosted at my expense, Nutreek
and Cupid are licensed — and it read as a pitch aimed at specific software.
Keep it general and keep it polite. In particular, do not describe the closed
projects as permanently closed: opening more of them up later is something Carlo
would like to do, and the page says so.

**The packets come first and then stay put.** The page exists to be donated
through, so the four services sit right under the label as sugar packets on a
tray (`.tray`), pinned to the top of the window for the whole page. On a phone,
under 52rem, the tray is fixed to the bottom instead, with `padding-bottom` on
the mat so the end of the page is never trapped under it. `scroll-padding` on
`html` keeps anything that takes focus clear of the tray (WCAG 2.4.11).

Each packet carries its service's own colour, taken from the service itself
rather than from memory: Buy Me a Coffee `#FFDD00` on `#0D0C22`, GitHub Sponsors
`#BF3989` light and `#DB61A2` dark (Primer's `--fgColor-sponsors`), PayPal
`#003087` light and `#0070E0` dark, Liberapay `#F6C915`. All four clear 4.5:1 in
both schemes. The icons are **drawn in this repo**, not lifted from anyone's
site: each says what kind of giving it is — a cup, a heart, a card, a recurring
arrow — so no third-party trademark artwork is redistributed here. If official
brand buttons are ever wanted instead, they should be downloaded from each
service's own brand page and committed to `assets/`.

Each packet hands the reader to that service. No payment details are ever
collected here, and there is no backend that could receive them — which is what
the till receipt on the page says, "Charged here 0.00".

The HomeBank attribution belongs on `cloudbank.html`, where it is a factual note
about that product's origins. It is deliberately **not** on the home page, where
it read as a disclaimer about the whole site.

## The CloudBank demo

`cloudbank.html#demo` links the demo instance. Since CloudBank's `:demo`
build, the demo has no shared sign-in: one button makes a throwaway account of
the visitor's own, deleted after two hours without use, every night and on every

## Voice

Plain and first-person, and no broader than the facts. Carlo is a software
developer with more than a decade of experience, currently a Full Stack
Software Developer at TeamSystem; the projects here are his own time. Earlier
drafts of this site opened with "Whole products, not demos" and a donate page
arguing about the ethics of paywalls, and both were asked to be toned down.
Describe what a thing is and let the reader decide whether it is impressive.
The room and the playful pages are allowed to be playful, but the words about
the work stay factual, and the professional home is plain throughout.

Never invent biography. LinkedIn (HTTP 999) and Instagram (login wall) cannot
be read programmatically, so anything personal on the About page came from
Carlo directly and the next fact should too.

## The design system

Three typefaces, from Google Fonts: **Bricolage Grotesque** for names and headings, **Atkinson
Hyperlegible** for reading, and **IBM Plex Mono** only for text that is literally machine text:
image tags, paths, commands, the values in spec tables and under "At a glance".

The professional home and pages (`pro.css`): a cool off-white ground (dark green-black in the
dark scheme) and one ink; the name is the only loud thing. Projects are ruled rows, not cards; a
project's accent shows only as its status line's square and its page's buttons.

The playful side: the ground is the mat, a green cutting mat with a 1 cm grid (`--mat`, darker
in the dark scheme). On it everything is a physical thing: paper (`--paper`, light in both
schemes, so text on paper is dark in both), tape, taped prints, index cards, sticky notes. The
only saturated colours are each product's accent, taken from its logo mark, and the donation
services' own colours.

Deliberately absent, and worth not reintroducing: gradient-filled words in headings, chips,
identical rounded cards, `·`-joined meta strings, and `→` appended to button text.

## The things that are coupled

**The product accents live once**, in `:root` in `styles.css` (`--cloudbank`, `--scs`,
`--planora`, `--nutreek`, `--cupid`, `--asf`, `--asf-pc`, `--coordinator-monitor`); a page or a
button takes one as `--c`, and `tools/sync.py` writes them into the professional pages. Light
accents clear 4.5:1 against white, because a button puts white text on `--c`.

**A project's facts live in its data file**, `data/projects/<id>.json`: its name, status line,
version, lede, the room object's short line and `aria-label`, About's line, the page's title and
descriptions, licence, stack, the professional page's `facts`, links and a curated set of
screenshots. `tools/sync.py` writes them into the pages between `<!-- data:<id>.<block> -->` and
`<!-- /data -->` (the label sheets, each `.fam-head` and `.fam-tab`, the room object's label,
the contact sheet's option, About's list, the professional home's rows, every `<title>` and
meta) and writes `pro/<id>.html` whole. Never edit inside those markers or in `pro/`: a release
or a status change is an edit to the data file and a run of `python tools/sync.py`, done by the
session, never by Carlo, and `checks/data.py` fails while a page differs. The playful scenery,
the long sections and their screenshots stay in each page's markup.

Some facts are still written by hand on the playful pages, and `checks/data.py` compares each
with the data: the licence as the page's prose names it, the stack tables of Nutreek, Planora
and Cupid, a data screenshot's alt, size and caption wherever it is shown (on its project's page
unless it is `pro_only`), CloudBank's fallback version in the ledger's Run it table, and the
links beyond the label sheet, which the page must still carry. The room's label round Planora's
jar is read by `room.js` from the bench's label, so it follows the data.

Adding a project: write `data/projects/<id>.json` (copy one, then run `python checks/data.py`,
which names every missing field); put the markers on its page (`title` and `og` in the head, and
`state`, `name`, `lede` and `actions` in its label sheet, empty: the generator fills them); add
its room object in `index.html` with its `aria` and `object` markers, its contact option
(`<option><!-- data:<id>.name --><!-- /data --></option>`), its entry in About's list (`about`)
and its professional row (`<!-- data:<id>.pro-row --><!-- /data -->` in the home's list); then
run `python tools/sync.py` and `python checks/data.py`. Its morph is a pair as well (Between
pages).

**`.label-sheet .state` is the status line.** One sentence, "Shipping, v3.8.1. Open source under
AGPL-3.0.", "In internal testing. Free, and hosted for you.", "Available to license." It is
`status` in the data file.

**CloudBank's version is not written by hand.** Every mention is a `<span data-cloudbank="stable">`
(or `"nightly"`, or `data-cloudbank-date`), and `site.js` fills it from `versions.json` on
CloudBank's `site-data` branch, which CloudBank's release and nightly workflows rewrite when they
publish. The text in the markup is only the fallback shown if that fetch fails: `version` in
`data/projects/cloudbank.json`; the span in the ledger's Run it table is a hand copy, which
`checks/data.py` holds to the same version.

**A morph is a pair.** Renaming or removing a room object, or the element its page shows first,
breaks its page transition: see the table under Between pages.

**Contact is mailto-based.** The Write to me sheet in the room is a form in
`<template id="sheet-contact">`; its inline script builds a `mailto:` URL to
`window.CONTACT_EMAIL`, set in a `<script>` in the head. Nothing is posted anywhere: there is no
backend, and adding one would be a real architectural change, not a tweak. Other pages, the
professional ones too, use plain `mailto:` links.

**The nav is repeated in every playful page.** Projects, About, Donate, GitHub, plus
`aria-current="page"` on the current one. Adding a page means touching all of them; there is no
include mechanism and that is the accepted cost.

## Conventions

Markup is Prettier-formatted-looking: two-space indent, ~100 column wrap, double
quotes, self-closing void elements. Match it by hand; no formatter is configured.

Files are LF. Writing them from Python needs `newline="\n"`, or Windows turns
every line ending into CRLF and the whole file shows as changed.

Accessibility is deliberate throughout: `aria-current="page"` in the nav, `alt=""`
on marks that repeat adjacent text, a skip link first on both homes, a label on every
control, every page that is not showing `inert`, a visible focus ring on every
interactive element, targets of 44 px or more, and contrast held at 4.5:1 or better in
both schemes. Keep it when editing.

External links carry `rel="noopener"`.

Commit messages are short imperative sentences describing the user-visible change,
e.g. "Update CloudBank to v3.0.0 on the card and detail page".
